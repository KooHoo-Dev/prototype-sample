- 훅은 자가 시험과 `settings.json` 명령 그대로의 모의 입력으로만 확인했다 → 첫 워크플로 뒤 `.claude/logs/guard.log`에 차단 · fail-open 줄이 어떻게 남았는지 본다
- 배포 워크플로(Deploy gallery)는 한 번도 실행되지 않았다. 액션 버전은 2026-10-02의 최신 릴리스다
- `ashen-cycle`은 규칙 이전에 만든 것이라 디버그 API 이름(`__ashen`) · 단일 HTML 파일 이름 · `_packages.json`의 `focus` · `visual`이 기준과 다르다 → 맞출지는 미정(부팅 표식과 `check:dist`는 2026-10-02에 맞췄다)
- 훅 G1이 서브에이전트의 `git ls-remote --tags <URL>`(원격 조회 · 읽기)을 두 번 막았다(배포 재검토 워크플로 · `guard.log`) → `ls-remote`를 읽기 허용 목록에 넣는다 → 반영
- 실제로 배포되는 모양(`dist`를 하위 경로에서 http로)을 보는 게이트가 없다 — `check:standalone`은 `file://`만 본다. 하위 경로 http 부팅 검사는 실측으로 됐다(헤드리스 Chrome · 6.4초 · 번들 404 대조군을 잡음) → 게이트를 `check:dist`로 바꾸고 단일 HTML은 선택 명령으로 내린다 → 반영
- 배포 재검토(Jay 결정): 전달은 GitHub Pages 갤러리 · `public: true`인 것만 올린다 · GCP는 더하지 않는다. 공개 전인 것을 링크로 보여 주거나 push 없이 올려야 하면 Firebase Hosting 미리보기 채널을 검토한다(만료 7~30일 · 접근 제한 아님 · 루트에 `firebase.json` 필요) → 반영
- 갤러리 배포는 테스트와 부팅 검사를 돌리지 않고 목록 페이지에 `noindex`가 없다 → 첫 배포 뒤에 워크플로에 넣을지 정한다
- 운영 자산을 고친 세션이 띄운 서브에이전트에는 고치기 전의 `CLAUDE.md`가 주입됐다(워크플로 목록은 새것) → 고친 세션에서는 서브에이전트를 띄우지 않고 새 세션에서 연다 → 반영(PIPELINE §10). 새 세션의 첫 서브에이전트가 새 문면을 받는지 한 번 확인한다
- 헤드리스 Chrome의 `--virtual-time-budget`은 `requestAnimationFrame`을 1~3번만 돌리고 실제 시간이 드는 await(오디오 렌더링 등)를 기다리지 않아 멀쩡한 부트를 떨어뜨린다 → 검사 스크립트를 디버깅 포트(CDP) 실시간 폴링으로 바꾼다 → 반영(`scripts/boot-probe.mjs`)
- 검토 에이전트가 `chrome.exe --version`을 실행하자 Windows에서는 Jay의 프로필로 Chrome 창이 떴다 → 브라우저는 검사 스크립트로만 띄운다 → 반영(CLAUDE.md 환경)
- Git Bash의 `grep`이 한글 패턴에서 죽으며 리포 루트에 `grep.exe.stackdump`를 남겼다(재현 조건 미확인) → `.gitignore`에 `*.stackdump` → 반영. 검색은 Grep 도구를 쓴다
- 배포 워크플로의 「Pages 설정」(configure-pages) 단계는 출력을 쓰는 곳이 없고 build 작업에 pages 권한이 없다 → 단계를 뺀다 → 반영(첫 실행은 여전히 미검증)
- 병렬 에이전트 4개 중 하나가 내장 브라우저 `tabs_create`에 실패했다(다른 하나는 성공 · 원인 미확인) → 화면을 보는 에이전트가 겹칠 때 같은 일이 나는지 첫 `/proto-new`에서 본다

## ashen-cycle · 2026-10-02 (첫 제작 — 이 리포의 규칙이 여기서 나왔다)

- 세션이 끊겨 첫 워크플로가 계약 개정 도중에 멈췄다 → 워크플로에 `from`과 비평 사본 파일을 둔다 → 반영
- 에이전트가 띄운 dev 서버가 고아로 남아 `strictPort`인 `npm run dev`를 막았다 → 포트 대역과 「자기 PID만 끈다」 → 반영
- 브라우저 창이 숨겨져 있어 화면 확인이 전부 정지 화면이었다 → 최소 부트부터 `__game.step(n)`을 둔다 → 반영. 실시간 재생과 소리는 끝까지 사람 몫으로 남았다
- 보스 근접 판정이 보이는 무기보다 1.3~3m 컸고 리뷰에서야 잡혔다 → 「판정은 보이는 것과 같다」 → 반영. 계약 단계에서 판정과 리그 치수를 한 표에 묶으면 더 일찍 잡힌다(미정)
- 체간을 한 방에 채우는 무기로 보스가 다시는 공격하지 못했다 → 「한 행동의 반복으로 무한히 이기는 루프」를 비평과 리뷰가 찾는다 → 반영
- 봇이 장검 약공격만 써서 대검 · 창 · 패링 · 유물의 밸런스를 재지 못했다 → 봇이 쓰지 않는 수단은 측정의 한계로 적는다 → 반영. 봇이 모든 수단을 쓰게 계약에 넣을지는 미정
- 순환이 올라갈수록 보상이 비용을 못 따라가는 구조(비용 제곱 · 보상 선형)를 산수 단계에서 못 잡고 봇 대전에서 잡았다 → 경제 비평이 "곡선이 발산 · 정체하지 않는가"를 본다 → 반영
- 계약이 3,300줄이라 에이전트마다 읽는 비용이 컸다(절 단위로 나눠 읽게 해 버텼다) → 계약을 패키지별 파일로 쪼갤지는 미정
- 연출(피격 점멸 · 섬광 · 텔레그래프 번쩍임 · 비네트)이 화면을 하얗게 덮는 것을 화면 패스에서야 줄였다 → 「연출이 정보를 가리지 않는다」 → 반영
- 결과 화면의 키 연타가 다음 화면의 행동(플라스크 · 레벨업)으로 샜다 → 「전환 직후의 에지 입력은 버린다」 → 반영
- PowerShell 실행 정책이 `npm`을 막아 Jay가 빌드를 돌리지 못했다 → `npm.cmd --prefix` 안내 → 반영
- `dist/index.html`을 더블클릭하면 빈 화면이다 → 단일 HTML 빌드와 `file://` 확인을 게이트로 → 반영
