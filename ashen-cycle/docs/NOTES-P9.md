## 봇 — 계약 본문(§12.3)에 더한 것

규칙 1~10의 순서와 `BOT`의 계약 값은 그대로다. 아래는 「사람이 패턴을 익히면 하는 일」을 규칙 안에 채운 것이다(수치는 `data/bot.js` 아래쪽에 이름을 붙여 뒀다).

1. **예고 중의 위협은 보스가 움직인 뒤의 자리로 어림한다.** 계약은 「보스 현재 위치 · facing(또는 조준점)」인데, `lunge`(판정 전에 최대 1.4~1.6m 전진) · `leap`(표식 없는 도약) · `charge`(판정 내내 달린다)는 현재 위치로 풀면 「닿지 않는다」고 읽고 그대로 맞는다. 바닥 표식(`state.telegraphs`의 `atk:<seq>:<i>`)이 있으면 그것이 정본이고, 없으면 남은 이동만큼 앞으로 옮겨 푼다. 돌진은 판정 셰이프를 남은 거리만큼 늘인 선으로 본다.
2. **이미 해소된 판정(`state.hitLog`)은 위협에서 뺀다.** 안 그러면 흘린 휘두르기의 남은 판정 구간에 구르기를 한 번 더 누른다(스태미나 22 낭비). 반복 타격(`interval > 0` — 브레스 · 불길)은 다음 간격의 시각을 위협으로 본다.
3. **연속기 판정(`chain[].at`)이 남은 후딜은 반격하지 않는다.** 발더 `slash_r` 후딜 0.30초에 `slash_l`이 45%(2페이즈 70%)로 이어진다 — 그 전에 약공격을 넣으면 맞는다. 회복 판단의 「남은 후딜」도 같은 식으로 줄여 읽는다.
4. **반격의 틈에 `recover`(그로기 뒤 일어남 — 무적 아님)를 넣었다.** `executed` · `phaseShift` · `intro`는 무적이라 때리지 않는다(`boss.invulnerable`).
5. **회복의 「안전」**: 거리 > 7m은 「보스가 예고/판정 중이 아닐 때」만 친다(멀리서 마시다 돌진 · 도약을 맞지 않게). 「남은 후딜 > 1.2초」에는 `parried` · `groggy` · `executed` · `recover` · `phaseShift`의 남은 시간도 넣었다.
6. **새 공격을 시작하지 않는 조건**: 위협이 0.6초(`attackCommit`) 안에 닿을 예정이면 약공격을 누르지 않는다(약공격이 구르기로 풀리기까지 약 0.5초).
7. **선입력해 둔 구르기의 방향**: sim은 소비 틱의 이동 의도를 구르기 방향으로 쓴다(§7.1). 그래서 구르기가 버퍼에 있는 동안은 같은 방향을 쥐고 있는다.
8. 구르기 도착점이 경계 밖 · 기둥이면 반대쪽으로, 양쪽이 막히면 아레나 중심 쪽으로 구른다. 후퇴 · 옆걸음은 경계 1.5m 안에서 벽을 따라 미끄러진다.
9. 봇은 **가드 · 패링 · 강공격을 쓰지 않는다**(계약 규칙에 없다). 그래서 `fight.parries`는 늘 0이고 체간은 약공격으로만 쌓는다.

## app — 계약에 없어 P9가 정한 것

- **개발용 URL 쿼리**: 계약 §11.6의 `?boss` · `?panel` · `?god`에 `?town=1` · `?bot=1` · `?fresh=1` · `?save=1` · `?nopause=1`을 더했다. **타이틀을 건너뛰는 쿼리(`boss` · `town` · `panel`)와 `fresh`는 「일회용 세션」이다** — 최소 부트와 같이 `createNewProfile(1)`로 시작하고, localStorage의 프로필을 읽지도 쓰지도 않으며(설정은 평소대로), 포커스 · 락 상실로 멈추지 않고, 이탈 확인(`beforeunload`)도 걸지 않는다. 자동화와 스크린샷이 매번 같은 판(시드 1)을 본다. 실제 세이브로 건너뛰려면 `?save=1`을 붙인다.
- **`__ashen.step(n, input)`**: 틱을 민 뒤 레이어 update + 렌더를 한다. n이 크면 `ceil(n / 240)`틱마다 레이어를 갱신한다(연출 이벤트가 한 프레임에 몰리지 않게 — `FxLayer`는 `update`에서 이벤트를 처리한다) · 렌더는 끝에 한 번. 측정: `step(600)` = 0.47초. 입력은 `input` 인자 > `setInput` > 봇 > 실제 입력 순. 패널(pause 포함)이 열려 있어도 봇 · 덮어쓰기는 통한다. `input`과 `setInput`의 에지(`*Pressed`)는 첫 틱에만 나간다.
- **`__ashen.pause(on)`** 은 패널 없는 일시정지다(자동화의 스크린샷에 pause 패널이 끼지 않게). `pause(false)`는 열려 있는 pause 패널도 닫는다. `__ashen.game`(Game 인스턴스)을 덧붙였다.
- **`__ashen.errors()`** 에는 `window.onerror` · `unhandledrejection`에 더해 **app이 잡은 레이어 예외**도 들어간다. 레이어 하나가 생성 · `update`에서 던지면 기록하고 그 레이어만 끈다(나머지는 계속 돈다). `sim.step`이 던지면 다음 `MODE_CHANGED`까지 틱을 멈춘다. 전이 중의 예외는 기록하고 막을 걷는다(검은 화면에 멈추지 않는다).
- **누산 루프의 스텝 상한** = `MAX_STEPS_PER_FRAME × ceil(timeScale)`. 계약 식 그대로(상한 5)면 60fps에서 배속이 5배를 넘지 못한다.
- **포인터 락 실패의 판정**: 「한 번이라도 실패하면 락 없는 클릭도 입력」의 실패는 **사용자의 캔버스 클릭에서 온 요청**만 센다. `UI_CLOSED` 뒤 app이 하는 재요청의 실패(Esc로 닫은 패널 — 사용자 활성화 아님)는 삼키기만 한다. 안 그러면 Esc 한 번에 「클릭 = 락 요청 + 공격」 모드로 넘어간다.
- **마우스 옆 버튼(3 · 4)** 은 캔버스가 아니라 `window`(capture)에서 막는다 — 계약의 「게임 화면 · 패널 공통」을 지키려면 패널 위의 클릭도 봐야 한다. `Alt` 조합 키도 `Ctrl` · `Meta`와 같이 건드리지 않는다(Alt+Tab의 Tab이 록온이 되지 않게).
- **저장**: 프레임 끝의 한 번에 더해 `pagehide` · `beforeunload` · 포커스 잃음에서도 밀린 저장을 쓴다(숨은 탭에서는 프레임이 돌지 않는다).
- **타이틀 배경**: 카메라가 마을을 천천히 돈다(0.05 rad/s). sim은 돌지 않고 레이어에는 실제 dt를 넘긴다(화톳불 · 안개가 살아 있다). 부팅은 검은 막에서 0.6초에 걷힌다.
- `InputCollector`의 덤(계약의 `consume` · `consumeLook` · `releaseAll` · `locked`는 그대로): `handlers`(app이 채우는 콜백) · `pollGamepad(dt)` · `requestLock()` · `exitLock()` · `notifyUiClosed()` · `dragMode`. `storage.js`의 함수는 마지막 인자로 저장소를 받을 수 있다(테스트용 — 기본은 localStorage).
- **테스트 파일을 하나 더 뒀다**: `test/bot.fight.app.test.js`(§1의 `<자기 테스트 이름>.*.js` 규칙 안). `Game.js`는 three · CSS를 끌어와 Node에서 import할 수 없어, DOM 없는 부분(`loop.js` · `screens.js` · `storage.js`)을 떼어 가짜 UI · 가짜 localStorage로 검사한다.

## 브라우저 스모크 (§12.5 — 실제 앱 · 포트 5191)

타이틀 → `E`(새 게임) → 마을 → 화톳불 `E` → 레벨업 → `Q` → 대장장이(강화 +1) → 상인(플라스크 충전) → 안개문 `E`, `E` → 발더전(봇 · 구르지 않음) → 사망 결과 → `R` 재도전(도전 횟수 2) → godMode 봇으로 격파 → 승리 결과(`R` 무시 확인) → `E` 마을로 → 새로고침 → 타이틀 기본 포커스 「이어하기」 → 프로필이 새로고침 전과 같다. 키는 `window`에 `KeyboardEvent`를 보내 실제 UI · 입력 경로로 눌렀다. **`errors()` 0 · 콘솔 오류 0.**

- 전환 시간(측정): 안개문 `E` → 보스전 화면 335ms(그 뒤 0.4초 걷힘) · 결과 `R` → 보스전 333ms.
- 저장: 타이틀에서 프레임이 돌아도 세이브 키가 생기지 않는다 · 깨진 문자열을 넣고 부팅 → `save.bak`에 원문 + 타이틀 안내 한 줄 + 「이어하기」 비활성 + 원래 키는 그대로 · 설정은 타이틀에서도 저장된다.
- 입력: 캔버스 첫 클릭은 락 요청에만 쓰인다 → 0.5초 뒤 드래그 모드 → 다음 클릭은 약공격 → 끌면 카메라가 돈다(자동화 창은 락을 주지 않는다). Esc → pause(틱 정지) → Esc로 닫히지 않음 → `E`로 재개.
- `?boss=valder&bot=1` · `?boss=fenrir&god=1` · `?boss=nihil&panel=pause`: 작업 중인 P10 · P11의 뷰 · 데이터 위에서도 오류 0.

## W3이 알아야 할 것

- **실시간 재생은 보지 못했다.** 이 환경의 Browser pane은 숨겨져 있어 `requestAnimationFrame`이 돌지 않는다 — 전부 `__ashen.step` / `game.frame(1/60)`으로 밀어 확인했다. 실제 rAF 루프(60 · 144Hz)의 체감 · 포인터 락을 쥔 채의 마우스 감도 · 락 중 Esc → pause 경로 · 게임패드 · 소리는 미확인이다.
- **작업 중에는 페이지가 수시로 새로고침된다**(다른 작업자가 파일을 고치면 vite가 전체 리로드한다) — 여러 호출에 걸친 자동화는 중간에 상태가 사라진다. 한 번의 스크립트로 끝내거나 `npm run build` 뒤 `vite preview`로 본다.
- `?boss=` 세션은 세이브를 쓰지 않는다. 「새로고침 후 이어하기」를 보려면 쿼리 없이 띄운다.
- HUD의 락 안내(「화면을 클릭하면 시점이 고정된다」)는 락을 줄 수 없는 환경(자동화)에서는 계속 떠 있다 — 계약(§10.1 W1 확정)이 드래그 모드에서도 `setPointerLocked(false)`를 요구한다. 거슬리면 P8 쪽에 「락 불가」 문구를 따로 둔다. (갱신: W4에서 드래그 모드 문구 「마우스를 누른 채 끌면 시점이 돈다」를 따로 두어 6초 뒤 사라지게 했고, W5에서 락 안내 문구를 「화면을 클릭하면 마우스로 시점을 돌린다」로 고쳤다.)
- 일시정지 → `[마을로]`의 포기 보상은 결과 패널 없이 마을로 간다(계약 §6.4 · §11.2 그대로) — 받은 잔불은 HUD 카운터가 굴러 올라가는 것으로만 보인다.
