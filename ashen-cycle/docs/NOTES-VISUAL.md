## 방법 (환경의 한계 포함)

- Browser pane이 숨겨져 있어 `requestAnimationFrame`이 돌지 않는다. `__ashen.pause(true)`로 앱의 루프를 세우고 `__ashen.step(n, input)`으로 틱을 밀어 **정지 화면**을 봤다(스크린샷을 찍는 순간 rAF가 한두 번 돌아 sim이 밀리므로 세워 둬야 원하는 순간이 찍힌다). 패널의 키 조작은 `window`에 `KeyboardEvent`를 보내 실제 UI 경로로 눌렀고, 마을의 `E`는 `step(1, {interactPressed})`로 눌렀다.
- 옆 · 위에서 보려고 임시로 카메라를 덮어썼고(끝나고 지운 `docs/_scratch/helpers.js`), 세부는 `body`에 CSS 확대를 걸어 봤다(스크린샷이 800×450으로 줄어 나온다).
- 뷰포트는 1280×720을 기본으로, 1920×1080은 일시정지 패널 · 발더전 HUD로 확인했다(글자 크기가 화면에 비례해 배치가 같다).
- **볼 수 없었던 것**: 실시간 움직임 전부 · 소리 · CSS 전환/애니메이션(숨은 탭에서는 진행되지 않는다) · 포인터 락을 쥔 상태. → 「사람이 확인할 것」.

## 본 것 — 고치지 않아도 됐던 것

- **패턴의 가독성**: 돌진(발더 · 펜리르)의 붉은 띠, 브레스의 부채꼴 + 흰 외곽선, 얼음 가시의 원 6개(채움이 차오른다), 2페이즈 포효의 고리, 불 인챈트는 세 아레나 모두에서 읽힌다. 설원의 밝은 바닥에서도 표식 바깥의 어두운 테가 있어 묻히지 않는다.
- **캐릭터**: 펜리르는 옆에서 늑대로(몸을 낮춘 돌진 예고 · 등의 가시가 danger 색으로 물든다), 니힐은 부유하는 마술사(왕관 · 후광 · 지팡이)로 읽힌다. 발은 지면에, 무기는 손에 붙어 있다(양손 무기의 왼손 포함). 구르기는 몸을 말아 한 바퀴(24% · 51% · 끝을 옆에서 확인). 처형당하는 니힐은 지면에 무릎 꿇는다.
- **카메라**: 록온 구도에서 보스의 가슴~머리가 플레이어 머리 위로 보인다(4.7m · 1.4m 거리). 벽을 등지면 줄어들고 올려다본다. 아레나의 기둥은 시야를 막지 않는다.
- **UI**: 패널 7종이 1280×720에서 겹침 · 잘림 없이 들어간다(가장 큰 것은 승리 결과 556px · 일시정지). 화면에 키 이름이 그대로 보이는 문자열은 없었다. 결과 패널의 수치(준 피해 % · 잔불 · 파편 · 교전 시간 · 받은 피해 · 패링 · 처형 · 구간 · 해금 · 레벨업 가능 횟수)가 sim의 값과 같다. 패널 키 조작(`W/S/A/D/E/Q/R`)이 전부 통한다.
- **흐름**: 안개문 → 보스전 460ms, 결과 `R` → 보스전 371ms(+ 걷힘 0.4초). 결과 패널의 `E`/`R`이 게임 입력으로 새지 않는다(마을에서 화톳불 패널이 열리지 않고, 승리 결과의 `R`은 무시된다). 일시정지는 Esc로 열리고 Esc로 닫히지 않는다. 보스전의 `[마을로]`는 확인 한 번.

## 사람이 확인할 것 (이 환경에서 볼 수 없었던 것)

`npm run dev`(또는 `npx vite --port <빈 포트>`)로 띄워 창을 **앞에 둔 채** 본다.

1. **타격의 박자**: 발더에게 약공격을 넣을 때 「칼이 닿는 순간 멈칫 → 스파크」로 느껴지는가(12번). 대검(판정이 긴 무기)과 창으로도. 어색하면 `playerView.js`의 `ACTIVE_CONTACT_T`(0.1)를 0.06~0.15 사이에서.
2. **번쩍임의 세기**: 줄인 뒤 타격감이 밋밋해지지 않았는가 — 약공격 · 강공격 완충 · 패링 · 처형을 차례로. 모자라면 `FxLayer.js`의 `LIGHT_GAIN`(0.14)을 0.2까지, 과하면 `particles.js`의 `flare.intensity`(2.6)를 내린다. 피격 비네트는 가장자리만 붉어지는지.
3. **채움광**: 카메라를 빠르게 돌릴 때 보스 · 기둥의 밝기가 「카메라를 따라 변한다」고 느껴지는가(특히 ember). 거슬리면 `arenaScene.js`의 `fillIntensity` 1.15 → 0.8.
4. **발더의 걸음**: 고민하며 걸어올 때 발이 바닥을 딛고 오는가(14번) · 걸음이 너무 성큼성큼하지 않은가.
5. **담 앞의 카메라**: 마을에서 안개문 옆 담 · 대장간 벽으로 뒷걸음질할 때 카메라가 부드럽게 올라가는가, 멀어질 때 튀지 않는가(11번).
6. **CSS 전환**: 보스 바가 차오르는 연출 · `YOU DIED`/`보스 격파` 배너의 등장 · 패널의 흔들림(잔불 부족) · 잔불 카운터가 굴러 올라가는 것 · 프롬프트의 페이드(숨은 탭에서는 진행되지 않아 처음과 끝 상태만 봤다).
7. **포인터 락**: 화면을 클릭해 락을 쥔 상태의 감도 · 락 중 Esc → 일시정지 → `[계속]`으로 락을 되찾는가 · 락 안내가 사라지는가. 게임패드.
8. **소리**: 전부(이 패스에서도 듣지 못했다).
9. **순간이동**: 니힐의 `blink` 뒤 록온 카메라가 도는 속도(상한 5.2 rad/s)가 멀미 없이 따라가는가.
