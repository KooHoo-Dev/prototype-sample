# NOTES-P11 — ui-panels (W2)

공개 이름(`createXPanel` 아홉 · `createTooltip` · `itemLines` · `compareLines` · `createBagGrid`)은 계약 그대로다. 아래는 계약이 비었거나 어긋나 P11 파일 안에서 정한 것 · 통합 때 볼 것.

## 통합 때 정할 것(남의 파일 · 계약)

1. **문자열 — 부록 B 키만 썼다.** P10 이 W2 에 더한 키(`label.gold` · `common.close` …)는 작업 중에 바뀌어(한 번 사라짐) 쓰지 않았다. 대신 조합한 곳: 상점 가격 줄 = `shop.gambleSlotPrice`({slot: 「사기」 · 「되사기」}) · 신비술사 비용 = `shop.rerollCost` + 「 · 망각의 정수 n」(키에 정수 자리가 없다) · 전설 · 세트 한 개 분해 확인 문면 = `shop.salvage`(「분해」 — 전용 키 `shop.salvageConfirm` 「{name}을(를) 분해한다」가 있으면 낫다) · 캐릭터 시트 묶음 머리 = 스탯 이름 둘셋을 ' · '로. 통합 게이트가 키를 더하면 그 자리만 바꾸면 된다.
2. **부분 수리 미리보기(`pnlLogic.repairPlan`)는 P6 `repairAll`의 순서를 다시 계산한다**(`REPAIR_ORDER` · `itemRepairRaw` — 버튼 「부분 수리 — n 골드」와 전 · 후 표에 필요한데 §6.13 에 조회 함수가 없다). `ui.panels.test`가 골드 6가지로 `repairAll` 결과(고친 칸 · 비용)와 같음을 고정한다 — P6 규칙이 바뀌면 이 테스트가 잡는다.
3. **P10 `widgets.gridNav`의 선택 인자 `onFocus` · `onEdge`**(계약 시그니처 밖 — P10 확장)로 영역 넘기기(§10.5-8)를 한다. P10 이 바꾸면 방향키로 옆 영역에 못 넘어가고 `KeyE`만 남는다.
4. 지금 `ui.strings.test`의 실패(키 없음)는 전부 `src/ui/analytics/*`(P12) — P11 파일의 키 리터럴은 0건 누락.

## P11 파일 안에서 정한 해석

- 인벤토리(겹쳐 보는 패널)의 `keys`에 §10.5-3 목록 + `KeyE`(영역 바꾸기 · `PANEL_KEYS.inventory.area` — 게임 키가 아니다) · `NumpadEnter`.
- 상점 · 보관함 · 신비술사의 가방 영역 Enter(· 클릭) = 장착(인벤토리와 같다). 팔기는 `X` · `V` · 끌어서 놓기만 — 클릭 한 번으로 팔리지 않게. 전설 · 세트 한 개 분해(`D`)만 확인을 거친다(되사기가 없다).
- 툴팁은 「그 아이템 위 · 장착 중인 것 아래」로 쌓고(폭 270px — 칸 옆에 들어간다), 화면 높이를 넘으면(반지 둘 등) 나란히. 변화 줄은 그 아이템 카드 안(반지를 둘 다 끼고 있으면 반지 1 · 2 각각). 고급(Alt · `LABELS` · 설정 `advancedTooltips`)이면 옵션마다 `[티어 n a–b]`(pow 옵션은 그 ilvl 배율을 곱한 범위 — `affixValue`와 같은 식). 신비술사의 옵션 목록은 늘 범위를 보인다.
- 「모든 거래 전 · 후」: 상점은 포커스한 것의 거래(사기 · 되사기 · 팔기 · 분해 · 제작 · 수량 · 무료 · 도박 · 재굴림 · 스킬 초기화)를 왼쪽 아래 표에, 수리 · 일괄 판매는 오른쪽 표에 늘 보인다. 장비 변화(시트 DPS · 생명 · 방어 · 저항)는 툴팁.
- 일괄 판매 대상은 `bulkSellPlan`(가방 · 일반/마법 · 잠기지 않음 · `isUpgrade` 아님) — 판매가 합계와 개수를 확인 문면에. `isUpgrade`는 시트 객체 × 아이템(재굴림 횟수)으로 기억한다(`upgradeOf` — 거래마다 가방 40칸을 다시 계산하지 않게 · 값은 그대로).
- 균열석: 기본 포커스 `defaultRiftLevel`(§10.6 식 그대로 · [1, 해금]) · 목록은 해금 + 3(표 끝 `RIFT.maxLevel`) · 진행 중(active · guardian)일 때만 확인 · 완료면 조용히 + 「남은 전리품 n개」 · 열기는 `actions.openRift` → 성공이면 패널을 닫는다.
- 스킬 트리 배치는 데이터 필드(branch · tier · kind)로만(`skillLayout` — 열 = 갈래 · 위 → 아래 단계 · 같은 단계면 액티브 · 패시브 · 변형). 변형은 대상 액티브 아래 들여 쓴 작은 노드 + 「변형 · 대상 이름」. 패시브 수치 전/후는 같은 스탯의 옵션 문면(`afx.<id>.line`)을 다시 쓴다(`nodeStatRows`).
- 신비술사: ① 장착 목록(+ 맨 아래 스킬 초기화) 또는 오른쪽 가방 격자에서 아이템 → ② 옵션(고정된 것이 있으면 그것에 포커스 · 나머지는 흐림) → ③ 후보 셋. Escape 는 한 단계 뒤(③이면 `rerollCancel` — 비용 없음). 패널을 닫아도 진행 중인 제안은 남는다(다시 열면 ③).

## 사람이 확인할 것

- 실제 마우스: 칸 위를 지날 때 툴팁이 따라가는 느낌 · 끌어서 놓기(헤드리스에서는 합성 이벤트로만 — 가방 ↔ 가방 · 가방 → 장비 칸 · 장비 → 가방 · 보관함 ↔ 가방 확인) · 실제 `Alt`를 누른 채 고급 툴팁.
- 1920 × 1080 화면(헤드리스는 1280 × 720 만 — 패널 크기는 px 고정이라 같은 크기로 가운데에 뜬다).
