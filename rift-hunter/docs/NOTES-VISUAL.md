# NOTES-VISUAL — 화면 · UX 패스

sim · 밸런스 게이트가 끝난 뒤, 실제 앱을 브라우저에서 처음부터 끝까지 돌려 「플레이어가 보는 것」을 확인하고 고쳤다. 고친 곳은 view · ui 뿐이고 sim · data 는 건드리지 않았다(용암 빛은 데이터 값 그대로 두고 view 의 그리는 법만 바꿨다).

## 1. 방법과 환경의 한계

- **클라우드 세션 · 내장 브라우저 없음.** 헤드리스 Chromium(소프트웨어 GL · swiftshader)을 CDP 디버깅 포트로 한 번 띄우고, 스크래치 드라이버(`docs/_scratch/drive.mjs` — 끝나고 지웠다)로 **같은 페이지에 여러 번 붙어** 실제 키 · 마우스 이벤트(`Input.dispatchKeyEvent` · `dispatchMouseEvent`)를 보내고 스크린샷을 찍었다. `probe:screen` 은 한 번 찍고 끝나서 이어지는 흐름(새로 고침 · 이어하기)을 볼 수 없었다.
- dev 서버 `vite --port 5422`. 1280×720 이 기본, 1920×1080 은 `Emulation.setDeviceMetricsOverride` 로.
- 헤드리스 새 모드에서는 `requestAnimationFrame` 이 실제로 돈다(약 15틱/초 — 소프트웨어 GL 이라 느리다). 그래서 앞부분은 실시간으로 클릭 · 키를 눌러 돌았고, 정확한 순간(판정 틱 · 예고 · 사망)은 `__game.pause(true)` → `step(n)` 정지 화면으로 봤다.
- 화면 좌표 → 월드: 카메라 식(§9.3 — 방위 45° · 앙각 55° · fov 40° · 24m · 앞당김 0.12)을 드라이버 안에서 그대로 풀어 몬스터 · NPC · 균열석 자리를 클릭했다.
- **볼 수 없었던 것**: 실제 프레임레이트 · 움직임의 연속성(걷기 발 미끄러짐 · 카메라 따라가기 · 흔들림 · CSS 전환) · 소리 · 실제 GPU 의 그림자/블룸 · 실제 마우스 감각(끌어서 놓기 · 휠). 스크린샷은 직접 열어 봤다. 아래 「사람이 확인할 것」에 남긴다.
- 도중에 dev 서버와 헤드리스 브라우저가 배경 작업 시간 한도로 한 번 꺼져 다시 띄웠다(내가 띄운 PID 만 · 결과에는 영향 없음).

## 2. 돌려 본 것(전체 루프 — 단계마다 `__game.errors()` 0 · 잡히지 않은 예외 0)

1. **쿼리 없이 첫 화면** `/` → 타이틀(계속하기 흐림 · 새 캐릭터 포커스) → Enter → 새 캐릭터 → ↓ 이름 「테스터」 입력 → Enter → 마을 + 「마을」 안내 카드(균열석 발밑 흰 고리 · 미니맵 균열석 점).
2. 균열석에 마우스(대상 = `riftStone`) → **좌클릭으로 걸어가 상호작용** → 균열석 패널(균열 1 「추천」 · 2~4 잠김 · 배율) → Enter → 막 → 균열 1(잿빛 동굴) + 조작 안내 카드 → Enter.
3. 땅 클릭으로 구울 떼 쪽 이동 → 적 위 누르고 있기(대상 고정 · 기본 공격 반복) · `Shift` + 누르기(제자리) — 틱 단위로 판정 틱 전후 프레임을 봤다.
4. **실패**: 떼 속에 서서 맞기 → 쓰러짐 → 0.3초 뒤 사망 패널(처치자 · 생명 2 · 수리비) → Enter → 부활 막 → 마을(복귀 안내 「Enter — 균열로 돌아가기」) → Enter → 같은 균열(생명 2). 키 2번.
5. 분석 패널(`` ` ``) → `]` 세 번 → 봇 탭 → 봇 켬 → 관전 배지 · 비모달 안내 → `step` 으로 밀어 **게이지 100% → 수호자 출현 예고 → 잿빛 마녀(시전 예고 · 하수인) → 처치 → 균열 완료**.
6. 봇 끔 → 완료 패널(시간 9:13 · 처치 291/10/…/1 · 사망 1 · 획득 18/10/3/1/0 · 골드 169 · 경험치 2,339 · 업그레이드 13) — **`rift.summary` 와 숫자가 같다**. Enter(계속 줍기) → `Alt` 누르고 이름표 → `T` 귀환(무릎 꿇기 + 시전 바) → 마을.
7. **진행**: 대장장이 클릭(걸어가 상호작용) → 사기 · 되사기 · 분해 · 제작 탭 · `E` 영역 바꾸기 / 잡화상 Enter = 포션 5개 구매(골드 169 → 109 · 포션 5 → 10) / 도박꾼 Enter = 주무기 도박(결과 툴팁 + 비교) / 신비술사 / 보관함 / 인벤토리 `I` · 스킬 `S` · 캐릭터 `C`(토글).
8. **새로 고침** → 타이틀 「계속하기」 활성 → Enter → 마을 · 레벨 4 · 해금 2 · 골드 · 가방 25 칸 그대로(저장 키 `rift-hunter:char:0` · `account`).
9. **붕괴**: `?class=warrior&rift=6` 에서 생명 1 로 두 번 죽음 → 「남은 생명 0 · 다음에 쓰러지면 균열이 무너진다」 → 복귀 → 다시 쓰러짐 → 붕괴 패널(붕괴 문구 · 이번 판 요약 · 「잃은 것: 수호자 보장 드랍 2 · 해금 +1」) → Enter → 마을(해금 그대로).
10. **입력 누수**: 완료 패널이 뜬 채 `T` `T` `Q` `T` 연타 → T 는 패널의 「마을로」로 처리돼 마을로 가고, **포션 · 두루마리 수는 그대로**(5 · 3 — 게임으로 새지 않음). 마을 도착 뒤의 `T` `Q` 도 소모 없음(마을 · 막 뒤 에지 버림).
11. 고정 상태 riftAffixes · riftGuardian · riftWitch · riftSwarm · riftWarrior · riftMage · riftLoot · riftDeath · riftComplete · lowLife · riftElites(+ 큰 지도) · skillTree · shops(`?panel=blacksmith|general|mystic` · 그 위에서 도박꾼 · 보관함 · 인벤토리)를 1280×720 에서, riftElites · 큰 지도 · riftDeath · 대장장이 · 인벤토리를 1920×1080 에서 봤다(고친 뒤 다시 찍은 것 기준).
12. 일시정지(`Esc`) → 설정(슬라이더 · 켬/끔) → 도움말(정예 속성 탭 12개 · 규칙) · 분석 드랍 시뮬레이터 1만 회(이론 vs 시뮬 · 히스토그램).
13. 특정 순간: 메테오 예고(바닥 원) → 낙하 바위 → 판정 틱의 원 안 밝아짐 → 불타는 바닥 / 구울 할퀴기 예비 → 판정 틱 / 레벨업 / 귀환 시전 / 플레이어 뒤 벽 낮추기(카메라 쪽 바위가 낮아지고 플레이어 보임).

### 고치지 않고 확인만 한 것(문제 없음)

- **타격 순간**: 전사 강타의 `actHit` 틱에 검이 구울 몸에 닿아 있고 예비 틱에는 머리 위로 올라가 있다(예고 자세에서 불꽃이 튀지 않는다). 구울 할퀴기도 예비(팔 들기) → 판정 틱 팔 끝이 플레이어 쪽.
- **메테오**: 예고 고리(주황 · 플레이어 소유라 붉지 않다) → 낙하 바위 → 판정 틱에 원 안만 밝아짐(화면 전체가 하얗게 뜨지 않는다) → 불타는 바닥.
- **적대 표식**: 감옥 · 역병 · 몰타르 · 냉기 노바 · 대지 분쇄 부채 · 잿불 비 원 5개 · 돌진 직선 · 역병 덩어리 원이 지하 묘지 · 잿빛 동굴 바닥 모두에서 붉은 테두리로 읽힌다.
- **벽 낮추기**: 카메라 쪽 바위 벽 사이 모서리에 세운 플레이어가 보인다(벽이 낮아짐).
- **입력 누수 · 키 2번 재도전 · 결과 수치 = sim · 새로 고침 이어하기 · 붕괴 경로** — 위 2절.
- 문자열 키가 화면에 그대로 나온 곳 없음(본 모든 패널 · HUD).
