# NOTES-P5 — loot (W1)

계약이 비어 있거나 어긋나 P5 파일 안에서 정한 것 · 다른 패키지가 알아야 할 것. 공개 이름 · 시그니처는 계약 그대로다(더한 export 는 아래 1).

## 다른 패키지가 알아야 할 것 (통합 게이트 확인)

1. **전설 · 세트 후보 규칙 — `specialCandidates(rarity, {slot, cls, ownClassOnly})`(theory.js · 더한 export)** 이 정본이다. `rollGear`가 그대로 쓴다.
   - 부위를 고른 굴림(`slot` 있음 — 도박 · 제작 · 재고 · 개발 장비)이나 `ownClassOnly`면 **자기 클래스 · 공용 행만**(「그 부위 · 클래스」). 부위 없는 드랍만 다른 클래스 전설 × `ITEM.otherClassLegend` · 다른 세트 `1 − ownSetChance`.
   - 빈 배열이면 희귀로 내린다. 지금 데이터로 후보가 없는 부위: 전사 = 보조 · 갑옷 · 반지 / 마법사 = 갑옷 · 장갑(전설) · 두 클래스 모두 목걸이 · 허리띠 · 반지 · 주무기 · 보조(세트).
   - **P6 `gambleOdds(char, slot)`는 `specialCandidates(r, {slot, cls: char.cls}).length === 0`이면 그 등급의 몫을 희귀에 더하면 된다**(같은 규칙을 다시 짜지 않는다).
2. **`Item.cls` — 전설은 그 행의 `cls`(공용 전설 `bloodPact` · `verdantSash`는 null) · 세트 조각은 그 세트의 `cls`** — 클래스 전용이다(W0 `makeItem`은 기본형 cls였다 · `makeItem`도 같은 규칙으로 바꿨다). 장착 검사(P6) · 툴팁(P11) · `isUpgrade`가 이 값을 본다. 다른 클래스 전설이 드랍에 섞이는 것(× 0.25)은 보관함으로 다른 캐릭터에게 넘기는 몫이다.
3. **`rerollAffix`는 「그 아이템의 다른 옵션」만 뺀다** — 지금 그 자리의 옵션 ID가 새 티어 · 값으로 다시 나올 수 있고, 두 번 부르면 같은 ID 후보 둘이 나올 수 있다(P6 `rerollOffer`가 다르게 보이고 싶으면 다시 부른다). 인덱스가 틀리면 null.
4. **`compareEquip`**: 클래스 · 레벨이 안 맞으면 `ok:false`(`'class'` · `'level'`)지만 `after` · `delta`는 「꼈다면」 값(툴팁이 붉게 보인다) · 끼울 칸이 없으면(`'slot'` — 부위가 다름 · 양손 무기를 낀 채 보조) `after === before` · delta 0 · 이미 낀 그 아이템이면 그 칸 · delta 0 · `upgrade:false`. `bestSlotFor`는 부위 규칙만 본다(클래스 · 레벨 · 양손은 장착 명령의 사유).
5. **`isUpgrade(stats, …)`는 `stats`를 「지금」으로 쓴다**(`ctx.stats` = `computeStats(char)` — 기본 riftLevel) · 유한수가 아니면 다시 계산한다. 반지 · 양손 · 보조 규칙은 `compareEquip`과 같은 함수(테스트가 600개로 대조).
6. **`slotDist(cls, mix = null)`** — 계약 시그니처 그대로면 일반 · 마법 · 희귀 장비의 부위(= SLOT_WEIGHTS). 선택 둘째 인자 `{rank, level, mf, blp, blpOn}`를 주면 전설 · 세트 부위를 섞은 정확한 분포(`createDropSim`의 `bySlot`과 대조할 값 — P12 분석 패널은 이쪽을 쓰면 된다).
7. **`createDropSim` 결과**: `maxGearGap` = 전설 **또는 세트** 없이 이어진 장비 드랍 수의 최대(불운 보정이 세는 수 — 켬이면 ≤ 400 · 지금 이어지는 구간 포함) · `killsToLegendary` = 전설만 · `result()`는 사본 · 같은 시드면 `run(n)`을 나눠 불러도 같은 결과. 불운 수(`blp`)는 `blpOn`이 꺼져도 센다(끔의 간격을 보이려고 — 확률에는 쓰지 않는다).
8. **10만 회의 「≤ 3%」는 1~2% 칸에서 표본 오차와 같은 크기다**(σ 상대 ≈ 2~3% — 예: 엘리트 L12 전설 1.2%는 시드에 따라 6%까지 벗어난다). 테스트는 고정 시드로 계약 목표를 보고, 따로 모든 칸 ≤ 4.5σ로 치우침을 본다(100만 처치에서 치우침 없음 확인). P12 패널은 작은 칸의 상대 오차에 표본 크기(또는 σ)를 같이 보이면 오해가 없다.

## P5 가 정한 해석

- `rollDrops`: 「gear → 2~5」 = §5.13의 2~5단계 · picks 를 다 굴린 뒤 보장 장비(`tc.guaranteed`) · 보장도 불운 수를 센다 · 드랍 묶음이 없는 등급(spawn) · 모르는 등급은 `{drops:[], blp}` · mf · gf 는 비율(음수 · NaN → 0).
- 등급 가중치의 등급 배율은 `RARITY.rank[rank]`(없으면 그 등급의 tc 키 · 그래도 없으면 1).
- 전설 · 세트 아이템의 단계 = 열린 가장 높은 단계(세트도 전설과 같게 읽었다) · 세트 조각 고르기는 「세트 0.8/0.2 → 조각 균등」을 가중치 한 번 뽑기로(분포는 같다).
- `rollItem(…, slotBias)` — 계약이 뜻을 적지 않았다: **옵션 ID → 가중치 배율**(선택 · null = 없음)로 읽었다. 지금 부르는 곳은 없다.
- `rollItem`의 난수 순서: 기본 값 편차(dmg → armor → bonus · 각자) → 옵션 수 → 옵션마다(고르기 → 티어 → 값 → skillPct 스킬) → 희귀 이름(a → b). 전설 · 세트인데 행이 없으면 희귀로.
- 마법구 추가 피해(bonus)도 「최대 ≥ 최소 + 1」 꼴(0~2 → ilvl 1에서 [0, 2]).
- `computeStats`: 합치는 순서는 데이터 배열 순서(EQUIP_SLOTS · SETS · SKILL_NODES — conds 순서도 노드 순서) · 숫자가 아닌 값(세이브가 깨진 옵션 · 기본 값)은 버린다 · 피해가 숫자가 아닌 무기는 맨손 · `dmgTakenReduce`는 `COMBAT.dmgTakenCap`(0.5)에서 자른다.

- 같은 희귀 장비 위에서 양손 대 한손 + 보조의 powerScore 비: 희귀 L1~L20 0.99~1.02(양손이 이기는 비율 47~66%) · 마법 1.03~1.05 · 일반 1.06~1.07(보조 기본 값만으로는 양손이 6% 앞선다). powerScore · ehp 에 **막기(방패 12%)가 들어가지 않아** 봇 · `isUpgrade`는 방패를 조금 낮게 본다.
